개인정보처리방침

시행일: 2026년 11월 8일 (앱 안 계정 삭제와 개인 베타 반영)

Sayday는 개발자가 개인적으로 쓰려고 만드는 일정 앱이며, 지금은 개인 베타 단계입니다. 이 문서는 현재 앱이 실제로 하는 일만 설명합니다. 다루는 정보가 늘어나면 기능을 켜기 전에 이 문서를 먼저 고칩니다.

요약

  • Google 계정으로 로그인하고, 같은 승인으로 받은 캘린더 권한으로 Google 캘린더와 양방향으로 동기화합니다. 보기로 고른 캘린더의 일정을 서버와 기기에 저장하고, Sayday에서 만들거나 바꾸거나 지운 일정을 Google 캘린더에 반영합니다.
  • 앱에서 입력한 일정과 할 일은 기기에 저장하고, 로그인한 동안 서버를 거쳐 같은 계정의 다른 기기와 동기화합니다.
  • 로그인한 동안 입력창에 쓴 문장을 보내면, 그 문장과 계정의 시간대만 Sayday 서버를 거쳐 OpenAI로 보내 일정·할 일로 해석합니다. 저장된 일정, Google 캘린더 데이터, 이메일 주소는 AI로 보내지 않습니다. 해석 결과는 사용자가 확인하고 저장을 누른 것만 저장됩니다.
  • 정보를 판매하거나 광고에 쓰지 않고, 아래에 적은 외부 서비스 외의 제3자에게 넘기지 않습니다.

처리하는 정보

계정 정보
Google 계정의 이메일 주소와 Google 계정 식별자입니다. Supabase 인증 서비스가 보관합니다. 로그인할 수 있는 이메일 주소 목록은 서버 함수의 비밀 저장소에 둡니다. 앱은 로그인 유지에 필요한 세션 토큰만 Android 보안 저장소와 macOS 키체인에 보관합니다.
일정·할 일 데이터
앱에서 입력한 내용과 Google 캘린더에서 가져온 일정입니다.
  • 일정: 제목, 날짜와 시각, 시간대, 반복 규칙, 장소, 메모, 알림 설정
  • 할 일: 제목, 메모, 마감, 예상 소요 시간, 완료 여부와 완료 시각, 알림 설정
  • 계획: 제목과 상태
  • 공통 설정: 시간대, 기본 알림 시각, 읽을 캘린더와 기본 저장 캘린더 선택
  • 그 밖에 항목 사이의 연결, 편집 가능 여부, 동기화 상태 같은 앱 내부 값
Google 캘린더 데이터는 아래 “Google 사용자 데이터”에 따로 적었습니다. 기기 안의 데이터베이스에 저장합니다. 로그인한 동안에는 자동으로 서버에 보내고 받아 같은 계정의 기기끼리 맞춥니다. 서버의 이 데이터는 앱 수준에서 암호화하지 않으므로 프로젝트 관리자인 개발자가 볼 수 있습니다. 로그인하지 않고 둘러볼 때는 기기에만 저장합니다.
동기화 기록
앱 설치마다 무작위로 만드는 기기 식별자, 항목별 변경 시각과 변경한 기기, 처리한 변경의 결과입니다. 같은 변경이 두 번 적용되지 않게 하려고 서버에 남기며, 변경 내용 대신 그 해시값을 저장합니다. 기기 모델이나 하드웨어 식별자는 수집하지 않습니다.
기기에만 두는 정보
알림 켜기·잠금 화면 제목 숨기기·화면 모드 같은 기기별 설정, 아직 보내지 못한 변경, 동기화 충돌 기록, 진단 기록입니다. 진단 기록은 오류를 찾기 위한 짧은 기록으로, 토큰·이메일·키처럼 보이는 값은 가린 뒤 저장합니다. 사용자가 설정 → 개발에서 직접 공유하거나 복사하지 않는 한 기기 밖으로 보내지 않습니다.
Google 연결 정보
Google 장기 토큰과 권한 범위, 연결한 기기 종류, 만료 시각, 연결 시각입니다. 토큰은 서버에 AES-256-GCM으로 암호화해 저장하고, 앱이 설치된 기기에는 저장하지 않습니다. 동기화를 이어 가려고 캘린더별 동기화 토큰, 마지막 동기화 시각, Sayday가 만든 캘린더의 식별자, 기존 캘린더에 쓰기를 열었는지 여부도 서버에만 둡니다.
AI 문장 해석
로그인한 동안 입력창에 문장을 쓰고 보내기를 누르면 그 문장을 일정·할 일 후보로 해석합니다.
  • 보내는 정보: 입력한 문장(최대 500자)과 공통 설정의 시간대입니다. 서버 함수가 현재 날짜와 시각을 붙여 OpenAI에 보냅니다. 이메일 주소, 계정 식별자, 저장된 일정·할 일, Google 캘린더에서 가져온 데이터는 보내지 않습니다.
  • 기존 일정 바꾸기·지우기: “수요일 치과를 5시로 옮겨줘” 같은 문장은 AI가 일정 이름과 날짜만 해석하고, 어떤 일정인지는 기기가 자기 데이터에서 찾습니다. 그래서 기존 일정의 내용은 AI로 가지 않습니다.
  • 거치는 곳: 앱 → Sayday 서버 함수(Supabase, 서울 리전) → OpenAI API(모델 gpt-6-luna). OpenAI API의 키는 서버 함수의 비밀 저장소에만 있고 앱에는 없습니다.
  • 보관: Sayday는 문장과 해석 결과를 서버에 저장하지 않고, 서버 함수 기록에도 문장을 남기지 않습니다(동작 이름, 항목 개수, 토큰 수, 비용만 남깁니다). OpenAI에는 저장하지 말라는 설정(store: false)으로 보냅니다. OpenAI는 API로 받은 데이터를 기본적으로 모델 학습에 쓰지 않지만, 남용 감시를 위해 최대 30일까지 보관할 수 있다고 안내합니다. Supabase가 함수 호출 기록을 자체적으로 남길 수 있습니다.
  • 기기에서: 해석 결과는 확인 화면이 열려 있는 동안 기기의 메모리에만 있습니다. 사용자가 고르고 저장을 누른 항목만 일반 일정·할 일이 되어 위 “일정·할 일 데이터”처럼 저장·동기화되고, 그 뒤에만 Google 캘린더 반영과 알림 예약이 일어납니다. 취소하면 아무것도 저장되지 않고 문장만 입력창에 남습니다. 진단 기록에는 해석 결과의 개수와 걸린 시간만 남깁니다.
  • 쓰지 않을 때: 로그인하지 않았거나 AI를 쓸 수 없는 동안에는 아무것도 보내지 않고, 직접 입력은 그대로 쓸 수 있습니다.
알림
알림을 예약할 때는 기기 안에서만 하며 알림 내용을 서버로 보내지 않습니다. 각 일정·할 일의 알림 설정값은 위 데이터와 함께 동기화됩니다.
개발용 검증 화면
개발용 빌드에만 있는 검증 화면과 별도의 Mac 검증 앱은 시험용 메모를 기기 안에 저장합니다. 개인 베타 설치본에는 이 화면이 없습니다. 이 화면들의 서버 공유는 시험 계정으로만 쓸 수 있었고, 그 계정과 서버의 시험 메모는 지웠습니다.
사용량과 운영 기록
허용된 사용자 목록과 기능별 사용 횟수, AI 해석의 사용자별 하루 요청 수와 프로젝트 전체의 월 비용(요청마다 미리 잡는 최대 비용과 실제 비용), Google Calendar API의 하루 요청 수(사용자 구분 없이 프로젝트 전체의 읽기·쓰기 합계)를 서버에 저장합니다. 서버 함수 기록에는 동작 이름, 상태 코드, 오류 코드, 처리한 개수를 남기며 토큰, 승인 코드, 이메일 주소, 일정 제목·메모는 남기지 않습니다. 서비스 제공업체가 요청 시각 같은 접속 정보를 자체적으로 기록할 수 있습니다.

Google 사용자 데이터

  • 요청하는 권한:
    • openid, email: 로그인한 사람의 Google 계정 식별자와 이메일 주소 확인
    • calendar.calendarlist.readonly: 구독 중인 캘린더 목록 보기
    • calendar.events.readonly: 모든 캘린더의 일정 보기
    • calendar.events.owned: 소유한 캘린더의 일정 보기, 만들기, 바꾸기, 지우기
    • calendar.app.created: 보조 캘린더를 만들고 그 캘린더의 일정 다루기
  • 사용: 이메일 주소와 계정 식별자는 로그인과 허용된 사용자 확인에만 씁니다. 캘린더 권한은 Google 캘린더 동기화에만 씁니다.
    • 캘린더 목록을 읽어 설정에 보여 줍니다.
    • 사용자가 보기로 고른 캘린더의 일정을 읽어 Sayday에 보여 주고, 같은 계정의 기기끼리 맞춥니다. 처음 연결할 때는 Google 캘린더 화면에 표시되는 캘린더가 골라져 있고, 설정에서 바꿀 수 있습니다.
    • 처음 연결할 때 “Sayday” 캘린더를 하나 만들어 새 일정의 기본 저장 위치로 씁니다. 개발용 빌드에서 요청하면 “Sayday 시험” 캘린더도 만듭니다.
    • 사용자가 Sayday에서 일정을 만들거나 바꾸거나 지우면 그 일정을 Google 캘린더에서도 만들고 바꾸고 지웁니다. 바꿀 때는 Sayday가 다루는 필드(제목, 시각, 장소, 설명, 반복 규칙)만 보내고 참석자 같은 다른 필드는 건드리지 않습니다. Sayday가 만든 캘린더에만 쓰며, 사용자가 설정 → 개발에서 “기존 캘린더에도 쓰기”를 켠 뒤에만 소유한 다른 캘린더에 씁니다.
    • 연결 전에 Sayday에서 만든 일정은 자동으로 올리지 않고, 사용자가 고른 일정만 Google에 올립니다.
    • 동기화는 앱을 열 때, 앱으로 돌아올 때, 무언가 바꿀 때, 지금 동기화를 누를 때와 앱이 열려 있는 동안 정해진 간격으로만 합니다. 앱이 닫혀 있을 때 서버가 혼자 Google을 읽지 않습니다.
  • 저장: 계정 정보와 연결 정보 외에, 보기로 고른 캘린더에 대해 다음을 Sayday 서버(Supabase)와 기기에 저장합니다. 서버의 이 데이터는 앱 수준에서 암호화하지 않으므로 프로젝트 관리자인 개발자가 볼 수 있습니다.
    • 캘린더: 이름, 권한(소유·읽기 등), 색, 시간대, Google 화면 표시 여부
    • 일정: 제목, 날짜와 시각, 시간대, 장소, 설명, 반복 규칙과 바뀐 회차, Google 일정 식별자와 버전값, Google 캘린더에서 여는 링크
    • 편집 가능 여부와 그 이유(소유하지 않은 캘린더, 참석자가 있는 일정, 복잡한 반복, 특수한 일정 종류). 참석자 목록 자체, 화상회의 정보, 첨부파일은 저장하지 않습니다.
    • Sayday와 Google에서 같은 일정을 서로 다르게 바꿨을 때, 사용자가 고를 때까지 Google 쪽 내용의 사본
  • 공유: 계정·토큰과 위 데이터를 보관하는 Supabase 외의 제3자에게 넘기지 않습니다. 광고나 AI 모델 학습에 쓰지 않으며, AI 제공업체에 보내지 않습니다.

Sayday의 Google 사용자 데이터 사용은 Google API 서비스 사용자 데이터 정책의 제한적 사용 요건을 포함해 이 정책을 따릅니다.

이용하는 외부 서비스

  • Supabase (서울 리전): 로그인, 데이터베이스, 서버 함수
  • Google: Google 로그인과 계정 승인, Google Calendar API
  • OpenAI (미국): 입력한 문장의 일정·할 일 해석. 위 “AI 문장 해석”에 적은 정보만 받습니다.
  • GitHub Pages: 이 안내 페이지 호스팅. GitHub는 방문자의 IP 주소를 보안 목적으로 기록합니다.

보관과 삭제

  • 일정·할 일을 지울 때: 다른 기기에도 삭제를 전하려고 서버에 삭제 표시를 남깁니다. 이때 제목, 장소, 메모는 지우고, 날짜·시각·반복 같은 나머지 값은 삭제 표시에 남습니다.
  • 로그인할 때: 로그인하지 않고 둘러보며 입력한 내용이나 다른 계정의 데이터가 기기에 있으면, 기기에서 지우고 서버에 있는 그 계정의 데이터로 다시 채웁니다. 둘러보며 입력한 내용은 서버로 보내지 않습니다.
  • 로그아웃: 그 기기의 세션만 끝내고 기기의 세션 토큰을 지웁니다. 기기에 저장된 일정·할 일과 서버의 데이터, Google 토큰은 그대로 남습니다.
  • Sayday에서 일정을 지울 때: Google 캘린더에 있는 일정이면 Google에서도 지웁니다. Google에서 지운 일정은 Google의 규칙에 따라 휴지통에 남을 수 있습니다.
  • 캘린더 보기를 끌 때: 그 캘린더의 일정을 Sayday 서버와 기기에서 삭제 표시로 바꿉니다(제목, 장소, 메모를 지움). Google의 일정은 그대로입니다.
  • Google 연결 해제(설정 → Google 캘린더): Google에 권한 회수를 요청하고 서버의 토큰과 동기화 토큰을 지웁니다. Google에서 가져온 일정은 Sayday에서 삭제 표시로 바뀌고, Sayday에서 만든 일정은 Sayday와 Google에 그대로 남습니다. Google의 일정은 하나도 지우지 않습니다. 다시 로그인하면 다시 연결됩니다.
  • Google 토큰: 다시 로그인하면 서버의 토큰을 새 토큰으로 바꾸지만, 이전 토큰의 Google 쪽 권한까지 회수하지는 않습니다. 회수하려면 위의 연결 해제를 쓰세요.
  • Google 계정에서 직접 회수: Google 계정의 서드파티 연결 화면에서 Sayday의 권한을 언제든 없앨 수 있습니다. 그러면 서버에 남은 토큰은 더 이상 쓸 수 없고, 앱은 다시 연결이 필요하다고 알립니다.
  • 계정과 데이터 삭제(설정 → 계정): 앱에서 직접 지울 수 있고, 지운 뒤에는 되돌릴 수 없습니다. 서버의 계정, 일정·할 일·계획·설정(Google에서 가져온 일정 포함), 동기화 기록, Google 토큰, 사용자별 사용 횟수를 지우고, Google에 권한 회수를 요청하며, 삭제를 누른 기기의 사본과 세션 토큰, 진단 기록도 지웁니다. 프로젝트 전체의 월 비용과 하루 Google 요청 수는 사용자를 가리키지 않는 합계라서 남습니다. Google 캘린더의 일정과 캘린더는 하나도 지우지 않습니다. Sayday에서 만들어 Google에 올린 일정도 Google에 남습니다. 같은 계정의 다른 기기는 곧 로그아웃되며, 그 기기의 사본은 그 기기에서 다시 로그인하거나 앱을 지울 때 사라집니다. Google이 권한 회수를 확인해 주지 않으면 앱이 알려 주고, 위의 Google 계정 화면에서 직접 없앨 수 있습니다. 프로젝트를 끝낼 때도 서버 데이터를 삭제합니다.
  • Android 기기의 데이터: 앱을 지우면 함께 삭제됩니다. 개인 베타 설치본은 Android 자동 백업을 끕니다. 이전 버전이 이미 올린 백업은 Google의 백업 보관 규칙에 따라 없어집니다.
  • Mac의 데이터: 앱을 지워도 응용 프로그램 지원 폴더의 데이터와 키체인의 세션 토큰이 남습니다. 앱 안에서 계정과 데이터를 삭제하면 둘 다 예시 데이터 상태로 돌아가고, 로그아웃만 하면 세션 토큰만 지워집니다. 기기의 데이터는 ~/Library/Application Support/local.sayday.mac 폴더(검증 앱은 local.sayday.m0 폴더)를 지워도 삭제됩니다.

보호 조치

통신에는 HTTPS를 사용합니다. AI 해석은 허용된 사용자만 쓸 수 있고, 한 사람당 하루 200회와 프로젝트 전체의 월 비용 상한을 넘으면 서버가 요청을 막습니다. 사용자별 접근 제어로 다른 사용자의 데이터를 읽지 못하게 하고, 앱은 일정·할 일 데이터를 서버의 표에 직접 쓰지 못하며 동기화 함수를 거쳐서만 씁니다. Google 토큰은 앱에서 직접 읽을 수 없으며, Google 캘린더 요청은 모두 서버 함수가 합니다. Google 요청은 하루 1만 건으로 제한합니다. 암호화 키는 데이터베이스와 분리해 서버 함수의 비밀 저장소에 보관합니다. 다만 어떤 시스템도 완벽한 보안을 보장할 수는 없습니다.
