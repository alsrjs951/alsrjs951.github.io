개인정보처리방침

시행일: 2026년 11월 8일

Sayday는 개발자가 개인적으로 쓰려고 만드는 일정 앱이며, 지금은 개발 단계입니다. 이 문서는 현재 앱이 실제로 하는 일만 설명합니다. 다루는 정보가 늘어나면 기능을 켜기 전에 이 문서를 먼저 고칩니다.

요약

  • Google 계정으로 로그인합니다. 로그인할 때 캘린더 권한도 함께 받아 서버에 암호화해 보관하지만, 지금 앱은 이 권한으로 Google 캘린더에 접근하지 않습니다.
  • 앱에서 직접 입력한 일정과 할 일은 기기에 저장하고, 로그인한 동안 서버를 거쳐 같은 계정의 다른 기기와 동기화합니다.
  • 정보를 판매하거나 광고에 쓰지 않고, 아래에 적은 외부 서비스 외의 제3자에게 넘기지 않습니다.

처리하는 정보

계정 정보
Google 계정의 이메일 주소와 Google 계정 식별자입니다. Supabase 인증 서비스가 보관합니다. 로그인할 수 있는 이메일 주소 목록은 서버 함수의 비밀 저장소에 둡니다. 앱은 로그인 유지에 필요한 세션 토큰만 Android 보안 저장소와 macOS 키체인에 보관합니다.
일정·할 일 데이터
앱에서 직접 입력한 내용입니다.
  • 일정: 제목, 날짜와 시각, 시간대, 반복 규칙, 장소, 메모, 알림 설정
  • 할 일: 제목, 메모, 마감, 예상 소요 시간, 완료 여부와 완료 시각, 알림 설정
  • 계획: 제목과 상태
  • 공통 설정: 시간대, 기본 알림 시각, 읽을 캘린더와 기본 저장 캘린더 선택
  • 그 밖에 항목 사이의 연결, 편집 가능 여부, 동기화 상태 같은 앱 내부 값
기기 안의 데이터베이스에 저장합니다. 로그인한 동안에는 자동으로 서버에 보내고 받아 같은 계정의 기기끼리 맞춥니다. 서버의 이 데이터는 앱 수준에서 암호화하지 않으므로 프로젝트 관리자인 개발자가 볼 수 있습니다. 로그인하지 않고 둘러볼 때는 기기에만 저장합니다.
동기화 기록
앱 설치마다 무작위로 만드는 기기 식별자, 항목별 변경 시각과 변경한 기기, 처리한 변경의 결과입니다. 같은 변경이 두 번 적용되지 않게 하려고 서버에 남기며, 변경 내용 대신 그 해시값을 저장합니다. 기기 모델이나 하드웨어 식별자는 수집하지 않습니다.
기기에만 두는 정보
알림 켜기·잠금 화면 제목 숨기기·화면 모드 같은 기기별 설정, 아직 보내지 못한 변경, 동기화 충돌 기록, 진단 기록입니다. 진단 기록은 오류를 찾기 위한 짧은 기록으로, 토큰·이메일·키처럼 보이는 값은 가린 뒤 저장합니다. 사용자가 설정 → 개발에서 직접 공유하거나 복사하지 않는 한 기기 밖으로 보내지 않습니다.
Google 연결 정보
Google 장기 토큰과 권한 범위, 연결한 기기 종류, 만료 시각, 연결 시각입니다. 토큰은 서버에 AES-256-GCM으로 암호화해 저장하고, 앱이 설치된 기기에는 저장하지 않습니다.
알림
알림을 예약할 때는 기기 안에서만 하며 알림 내용을 서버로 보내지 않습니다. 각 일정·할 일의 알림 설정값은 위 데이터와 함께 동기화됩니다.
개발용 검증 화면
Android 앱의 설정 → 개발에 있는 검증 화면과 별도의 Mac 검증 앱은 시험용 메모를 기기 안에 저장합니다. 이 화면들의 서버 공유는 시험 계정으로만 쓸 수 있었고, 그 계정과 서버의 시험 메모는 지웠습니다.
사용량과 운영 기록
허용된 사용자 목록과 기능별 사용 횟수를 서버에 저장합니다. 서버 함수 기록에는 동작 이름, 상태 코드, 오류 코드를 남기며 토큰, 승인 코드, 이메일 주소는 남기지 않습니다. 서비스 제공업체가 요청 시각 같은 접속 정보를 자체적으로 기록할 수 있습니다.

Google 사용자 데이터

  • 요청하는 권한:
    • openid, email: 로그인한 사람의 Google 계정 식별자와 이메일 주소 확인
    • calendar.calendarlist.readonly: 구독 중인 캘린더 목록 보기
    • calendar.events.readonly: 모든 캘린더의 일정 보기
    • calendar.events.owned: 소유한 캘린더의 일정 보기, 만들기, 바꾸기, 지우기
    • calendar.app.created: 보조 캘린더를 만들고 그 캘린더의 일정 다루기
  • 사용: 이메일 주소와 계정 식별자는 로그인과 허용된 사용자 확인에만 씁니다. 캘린더 권한은 로그인할 때 함께 받아 토큰을 서버에 보관하지만, 지금 앱은 이 토큰으로 Google 캘린더의 캘린더나 일정을 읽거나 바꾸지 않습니다. 이전 시험 단계에서는 연결 상태 확인과 시험용 캘린더 만들기·지우기에만 썼습니다. Google 캘린더 동기화를 켜기 전에 이 문서를 먼저 고칩니다.
  • 저장: 위에 적은 계정 정보와 연결 정보만 저장합니다. Google 캘린더의 캘린더와 일정 내용은 서버에 저장하지 않습니다. 앱에서 직접 만든 일정은 Google 데이터가 아니며 위의 일정·할 일 데이터처럼 저장합니다.
  • 공유: 계정과 토큰 보관에 쓰는 Supabase 외의 제3자에게 넘기지 않습니다. 광고나 AI 모델 학습에 쓰지 않으며, AI 제공업체에 보내지 않습니다.

Sayday의 Google 사용자 데이터 사용은 Google API 서비스 사용자 데이터 정책의 제한적 사용 요건을 포함해 이 정책을 따릅니다.

이용하는 외부 서비스

  • Supabase (서울 리전): 로그인, 데이터베이스, 서버 함수
  • Google: Google 로그인과 계정 승인, Google Calendar API
  • GitHub Pages: 이 안내 페이지 호스팅. GitHub는 방문자의 IP 주소를 보안 목적으로 기록합니다.

문장 해석을 위한 AI 기능은 아직 앱에 연결되어 있지 않습니다. 연결하기 전에 어떤 정보가 어디로 전송되는지 이 문서에 먼저 적습니다.

보관과 삭제

  • 일정·할 일을 지울 때: 다른 기기에도 삭제를 전하려고 서버에 삭제 표시를 남깁니다. 이때 제목, 장소, 메모는 지우고, 날짜·시각·반복 같은 나머지 값은 삭제 표시에 남습니다.
  • 로그인할 때: 로그인하지 않고 둘러보며 입력한 내용이나 다른 계정의 데이터가 기기에 있으면, 기기에서 지우고 서버에 있는 그 계정의 데이터로 다시 채웁니다. 둘러보며 입력한 내용은 서버로 보내지 않습니다.
  • 로그아웃: 그 기기의 세션만 끝내고 기기의 세션 토큰을 지웁니다. 기기에 저장된 일정·할 일과 서버의 데이터, Google 토큰은 그대로 남습니다.
  • Google 토큰: 앱 안에는 아직 Google 연결 해제 기능이 없습니다. 다시 로그인하면 서버의 토큰을 새 토큰으로 바꾸지만, 이전 토큰의 Google 쪽 권한까지 회수하지는 않습니다.
  • Google 계정에서 직접 회수: Google 계정의 서드파티 연결 화면에서 Sayday의 권한을 언제든 없앨 수 있습니다. 그러면 서버에 남은 토큰은 더 이상 쓸 수 없습니다. 서버의 토큰 자체를 지우려면 아래 문의로 요청하세요.
  • 계정과 서버 데이터: 앱 안에는 아직 계정 삭제 기능이 없습니다. 요청하면 개발자가 계정을 삭제하며, 이때 서버의 일정·할 일 데이터, 동기화 기록, Google 토큰, 사용 횟수 기록도 함께 지워집니다. 프로젝트를 끝낼 때도 삭제합니다.
  • Android 기기의 데이터: 앱을 지우면 함께 삭제됩니다. 다만 Android 자동 백업이 켜져 있으면 기기의 일정·할 일과 메모가 사용자의 Google 백업에 포함될 수 있습니다.
  • Mac의 데이터: 앱을 지워도 응용 프로그램 지원 폴더의 데이터와 키체인의 세션 토큰이 남습니다. 앱 안에서 로그아웃하면 세션 토큰이 지워지고, 기기의 데이터는 ~/Library/Application Support/local.sayday.mac 폴더(검증 앱은 local.sayday.m0 폴더)를 지우면 삭제됩니다.

보호 조치

통신에는 HTTPS를 사용합니다. 사용자별 접근 제어로 다른 사용자의 데이터를 읽지 못하게 하고, 앱은 일정·할 일 데이터를 서버의 표에 직접 쓰지 못하며 동기화 함수를 거쳐서만 씁니다. Google 토큰은 앱에서 직접 읽을 수 없으며 서버 함수로만 다룹니다. 암호화 키는 데이터베이스와 분리해 서버 함수의 비밀 저장소에 보관합니다. 다만 어떤 시스템도 완벽한 보안을 보장할 수는 없습니다.

  • 2026년 11월 7일: 처음 게시하고, 같은 날 캘린더 권한 범위를 넓히며 고쳤습니다.
